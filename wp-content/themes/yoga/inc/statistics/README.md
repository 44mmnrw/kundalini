# Статистика пользователей

В админке: **Пользователи → Статистика** и блок **Статистика пользователя** в профиле. Просмотр доступен администраторам с `manage_options`; для профиля дополнительно проверяется `edit_user`.

## Практики

Таблица `{prefix}yoga_practice_activity` создаётся через `dbDelta` при первом открытии админки администратором после установки изменений. Версия схемы хранится в `yoga_practice_activity_version`, дата начала учёта — в `yoga_practice_activity_since` (UTC). Нужны права БД на создание таблицы.

Счётчик работает для вошедшего пользователя, когда практика опубликована и доступна целиком: по подписке, как открытая практика или при выключенном ограничении разделов. Просмотр страницы и выбор длительности ничего не записывают. Запуск — фактическое начало таймера или воспроизведения. Пауза, продолжение и перезагрузка вкладки используют один UUID сеанса. Повторное выполнение после завершения получает новый UUID; другой сеанс браузерной вкладки также начинает новый учёт.

Завершение записывается после окончания всех упражнений (любой версии каждого упражнения), окончания полного видео или нажатия «Практика выполнена» после запуска. Ручной переход к следующему упражнению не засчитывает его выполнение. Прогресс упражнений сохраняется в `sessionStorage` на время сеанса вкладки. При запрете хранилища счётчик работает до перезагрузки.

AJAX проверяет авторизацию, nonce, опубликованную практику и доступ. ID пользователя берётся из текущей сессии. Уникальный ключ `(user_id, session_key)` и атомарное обновление завершения защищают от повторов запросов. Старые запуски не восстанавливаются. Старое поле `completed_practices`, если заполнено, показано отдельно.

## Садханы

Отчёт читает существующую таблицу плагина `kundalini-sadhanas`. Состояние пропущенного цикла рассчитывается без сохранения: просмотр отчёта не нормализует циклы и не запускает уведомления. Дни суммируются по циклам, включая прерванные; текущая серия — максимальное количество дней среди циклов с последней отметкой сегодня или вчера в часовом поясе пользователя. Удалённые пользователи исключены из статистики активности.

## Оплаты

Заказы читаются через публичный API WooCommerce пакетами по 100, без SQL к таблицам заказов; поддерживаются обычное хранение и HPOS. В итоги входят оплаченные и возвращённые заказы. Технические заказы `_ytr_card_binding=yes` исключены, остальные неоплаченные заказы видны только в истории. Учитываются частичные и полные возвраты; валюты не суммируются между собой. Бесплатные покупки тарифов входят в количество покупок.

Выручка по тарифам использует стоимость позиций после скидок с налогом. Возвраты без привязки к позиции распределяются пропорционально оставшейся стоимости. Варианты товара объединяются по родительскому товару. При создании позиции заказа сохраняется признак тарифа `_yoga_statistics_tariff`, чтобы последующее удаление товара не потеряло его тип. Старые удалённые товары без этого признака невозможно надёжно отнести к тарифам.

Общие финансовые итоги кешируются на 5 минут; изменения заказов и возвратов сбрасывают кеш. Итоги пользователя и история его заказов запрашиваются при просмотре профиля. История связана с ID покупателя; гостевые оплаты показаны отдельно в общем отчёте.

## Проверки

Из корня проекта:

```text
php wp-content/themes/yoga/tests/user-statistics.php
node wp-content/themes/yoga/tests/practice-statistics.js
php wp-content/themes/yoga/tests/user-statistics-mysql.php
```

Первые две проверки используют фикстуры без WordPress, сети, оплат и писем. Последняя требует работающую локальную MySQL и читает реквизиты из локального `wp-config.php`; подключение разрешено только к `localhost`/`127.0.0.1`. Она создаёт только `TEMPORARY`-таблицы с уникальным префиксом, которые удаляются при закрытии соединения. Существующие таблицы проекта не изменяются.
